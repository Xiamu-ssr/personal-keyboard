# App / Cloud / Spec 架构

## 目录与职责

    app/    Android 键盘、录音、OCR、本地历史和记忆
    cloud/  产品账号、权益账本、模型代理、提示词、付费同步、运营后台
    spec/   基础域卡片、两张业务图、业务与接口约定

原 `android/` 已迁至 `app/`，不保留重复路径。App 不内置供应商密钥；Cloud 提供产品 API，供应商可以替换。Spec 的免费额度直接读取 `cloud/config/plans.json`，提示词读取 `cloud/prompts/`，避免图、文档与后台配置各抄一份。

## 调用边界

    App ── HTTPS / WebSocket ── 产品域名
                                  ↓ TLS 反向代理
                              Cloud API 容器
                               ├─ 账号与权益 / PostgreSQL
                               ├─ ASR 实时代理 → Qwen Message
                               ├─ 提示词与文字任务 → 文字供应商
                               ├─ 后台 worker / 重试与对账
                               └─ 付费私有存储 / 同步清单

默认 ASR 为 `qwen-audio-3.1-asr-flash-message`。原生实时协议由 Cloud 代理，不把它塞到文字模型的 Chat API。ASR 和所有文字推理都走 Cloud；普通输入和 OCR 留在设备。云服务按任务鉴权、预留、调用和结算，不直接相信客户端报告的消耗。

App 首版按要求内置 `https://106.14.73.99/keyboard-api`；正常校验公开证书，不关闭 TLS 验证。后续改用 HTTPS 域名。域名解析指向服务器或负载均衡；反向代理转到 loopback 容器端口。换机器通常只改 DNS / 代理，不必重新发 APK。域名也不是凭空发现，换域名需预置迁移或新版 App，证书必须受设备信任。

首期一个 API 服务、后台 worker、独立持久化数据库即可，无需 Kubernetes。镜像不包含数据和密钥，数据库 / 私有存储保留在持久卷或托管服务，按项目独立网络、配置、备份；不复用同机其他产品的数据。

## 任务与提示词

| 任务 | Cloud 组装 | 发给谁 | 回到哪里 |
| --- | --- | --- | --- |
| ASR | 音频＋热词＋少量近期文字；接口参数控制规整 | Qwen Message | Cloud 计量，App 展示与编辑 |
| 个人改写（可关） | 改写提示词＋最终转写＋适用文风 | 文字模型 | Cloud 校验，App 填入 |
| 军师 | 军师提示词＋OCR＋意图＋相关热词 / 文风 / 人物 | 文字模型 | Cloud 校验和结算，App 展示三条建议 |
| 记忆整理 | 学习提示词＋增量历史＋来源许可＋相关旧记忆 | 文字模型 | Cloud 校验结构，本机按版本合并 |

系统提示词由 Cloud 持有并版本化，不把 OCR 或用户历史当作系统指令。模型 / 提示词版本、上下文 revision 与 usage 关联任务 ID。代码负责身份、数据范围、预算和过期结果，不能只靠提示词。

## 账本与状态

用户可见权益单位是转写字符和军师生成次数；供应商单位是音频秒、token 和费用，后台分开显示。预留 / 结算 / 释放是数据库事务，用户与幂等任务键、欢迎赠送、支付交易均有唯一约束。只在校验成功结果后完成结算，断线恢复原任务；供应商已花费但用户失败的成本进入故障账，不伪装成用户成功用量。

套餐发布后不可原地修改，发放时保存快照。新版本不追扣已有用户，也不重发欢迎礼包；存量调整使用明确的迁移与审计。后台和用户 API 分权限，管理员访问需单独认证，私人聊天内容不进入默认后台日志。

本机资料用 revision 和删除墓碑合并。云模型不能直接写设备目录。付费同步上传加密增量包而非活动 SQLite / WAL；免费用户依然能得到本地学习后的热词与文风。详见 [历史与记忆](memory-and-sync.md)、[商业服务](commercial.md)。
