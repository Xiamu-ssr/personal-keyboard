# App / Cloud / Spec 架构

目录保持 app/、cloud/、spec/。域表示长期持有数据与责任的边界；动作和提示词放在传输卡片，不拆成工作流节点。

| 域 | 子节点 | 责任 |
| --- | --- | --- |
| 用户手机 | 麦克风、聊天与输入框 | 声音 / 截图、本人编辑和发送 |
| 输入法 App | 历史、记忆缓存 | 本机历史主本、交互、离线缓存和待上传变化 |
| Cloud | 代理、账户与权益、热词、文风、人物 | 模型与任务、身份结算、个人记忆主本和增量同步 |
| 供应商 | 语音模型、语言与视觉模型 | 接收必要材料，返回结果及用量 |
| 运营后台 | 配置与监控 | 脱敏账户、用量、故障与套餐管理 |

## 数据与更新

文字历史和军师截图留手机。App 使用时记录变化并提交有界增量；Cloud 接单后独立运行，取相关旧记忆、组装提示词并调用 LLM。LLM 提结构化操作，Cloud 验证来源、版本及冲突后事务落库；App 按同步游标拉取完整变更记录和删除标记，更新缓存。

热词是一条词记录；文风是按场景关联的小档案；人物身份和人物事实分别有稳定 ID。只更新变化的记录，不重写整库，不让模型执行 SQL 或编辑目录。缓存与热词接入个人词库后可影响离线候选排序；文风和人物主要服务语音整理与军师。详细契约见[历史与记忆](memory-and-sync.md)。

历史变化按 ID、修订与变化序号跟踪，旧记录改稿也重新入队。明确纠词尽快处理；较多文风、人物证据合批，Cloud 按 token 预算分片。无固定五小时扫描，无每用户 harness 容器。

## 模型与部署

商业模型统一 App → Cloud → 供应商。Cloud 持有凭据、路由和提示词；改写、军师、记忆学习是代理的不同任务。军师一次多模态读取截图、相关人物关系、文风和近期表达，同次返回回复与识别出的聊天内容，不另做 OCR 前置。

首版 APK 内置 https://106.14.73.99/keyboard-api 并正常校验证书；后续可迁稳定 HTTPS 域名。一个 API 容器、后台 worker 与持久化 PostgreSQL 足够首期，密钥不入镜像。任务完成不依赖手机保持进程存活；键盘下次使用时继续同步。

个人记忆同步属于基础账户能力；完整历史 / 截图云备份另按付费权益开放。任务材料临时处理、个人记忆持久存储与历史备份分开说明，不声称供应商零留存。

## 迁移边界

这是目标协议。当前 0.4 尚未完成 Cloud 个人记忆主本、事实记录、版本同步、直接多模态和关联历史迁移；当前提示词仍是旧运行时实现。免费额度仍读取 cloud/config/plans.json，本轮不改运行时套餐来假装迁移完成。见[当前实现](implementation.md)。
