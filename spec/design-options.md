# 已选方案与待定项

域与子节点按本轮要求改好。已确认的选择与仍可讨论的建议分开；[调研依据](research.md)与[已发布实现](implementation.md)另列。本轮只改 Spec，没有重新发布 APK 或迁移 Cloud。

## 本轮已选择

- 军师直接多模态看图，不另搭 OCR 前置。
- 明确的听写纠词自动加入热词，保留来源并可撤销；文风变化与人物冲突先确认。
- 语音最终转写、军师截图进入本机历史。
- 历史分转写、军师两类，关联本人的选择与实际发送内容；取不到实际发送内容不冒充已取得。
- 军师带本次截图、相关人物关系、本人文风与近期最终发送内容，不附独立热词表。

具体视觉模型、整理触发条件、预算、保留期限和备份图片范围仍未定。

## 我的建议与取舍

| 问题 | 我推荐的方案 | 另一种取舍 |
| --- | --- | --- |
| 热词从哪来 | 手动词条直接生效；明确的听写纠词作为主要学习信号；历史里的高频专名只补充候选 | 只手动维护，更可控，但不会自己适应 |
| 文风怎么学 | 只看本人的表达与反复修改，提炼短偏好及少量例句；模型自己的润色不反复喂给自己 | 只选预设风格，简单但不像本人 |
| 何时整理 | App 选新增 / 修订历史，空闲联网时交 Cloud 合批；Cloud 按模型预算分片，LLM 提建议，App 校验落库 | 固定周期也可做，但目前没有理由指定五小时 |
| 人物从哪来 | 有说话人归属的截图 + 本人明确陈述；保留“谁说的 / 何时 / 哪条来源” | 仅用截图更保守，但会漏掉本人补充的信息 |
| 军师怎么读屏 | 一次多模态请求，看截图并给回复；不额外搭 OCR 前置 | 本地 OCR + 文字模型，原图不上传，但要维护气泡、引用、说话人等解析 |

热词优先快速适应，文风和人物谨慎累积，不用同一条“定时任务”一锅煮。已选明确热词自动且可撤销；文风变化与人物冲突先保留候选。这一自动程度已按本轮选择更新；什么算可靠纠词需要样本验证，不设虚构的次数阈值。

## 历史到底存什么

已明确分转写、军师两类。推荐一次输入一条记录：来源、实际填入稿、最后一份可靠结果；军师的选中回复就是实际填入稿，不重复造“最终答案”。**不存逐次编辑快照**。实际填入稿保留是为了不把 LLM 润色误判成用户修改。

结果必须带证据状态；安卓不能保证拿到所有 App 的最终发送文本。未知就留草稿 / 缺失，军师近期历史只取同对话已确认发言，不用原 ASR 顶替。截图与本人的明确陈述都可支持人物，但要标谁说的；详细最小记录见[历史与记忆](memory-and-sync.md)。

原始录音默认不留、图片压缩去重、显示占用并可批量清理，是存储建议；保留期限、容量和备份是否包含图片尚未决定，不擅自设定永久或到期删除。

## “整理”具体是什么

**App 选增量 → Cloud 编排与分片 → 供应商 LLM 提结构化更新 → App 校验写入本机。** 更新的是数据，不是训练模型。来源指针要跟踪历史的修订，旧记录补到最终发送内容也重新入队；原历史保留，不逐次重读全库。

我推荐有边界的后台任务，暂不需要给每个用户重启一个通用 Agent / harness 容器。什么时候攒成一批、花多少预算，由实际样本和成本来定。

## 两个容易混淆的边界

- **本机保存 ≠ 完全不上传。** ASR 需要音频，直接多模态需要本次截图，记忆分析需要选中的文字。云端临时处理、供应商留存政策、付费云备份是三件事；当前没有“供应商零留存”的验收结论。
- **本人草稿 ≠ 对方事实。** 本人说“她下周出差”可记为本人陈述；本人准备回复“周五见”不能记成对方已同意约会。热词、文风、人物共享来源，但分别判断。
