# 历史与个人记忆

本轮明确的结构：App 持有历史、热词、文风、人物。历史是原始来源，个人记忆是面向未来的摘要；均以本机为主本。已选自动热词、谨慎确认文风变化与人物冲突；其余机制见[方案与待定项](design-options.md)，没有固定五小时工作流。

## 已确认的保存内容

- 语音：成功后的最终转写，进入本机历史。
- 军师：本次截图，进入本机历史。
- 免费账户不提供云备份；付费云备份由产品管理，不向用户暴露存储供应商配置。

## 建议补充的记录

| 同一次历史记录 | 建议保存 | 能说明什么 |
| --- | --- | --- |
| 语音输入 | 原转写、实际填入版本 | 模型输出与真正上屏的区别 |
| 可归属的修改 | 最后观察改稿、范围、时间与状态 | 本人改过什么，不能证明已经发送 |
| 军师输入 | 截图、模型文字观察、意图、建议 | 本次依据与建议；读图结果可能出错 |
| 派生记忆 | 内容、人物归属、来源、修订 | 为什么形成这个词、偏好或人物信息 |

建议只观察自己填入的范围，利用编辑器会话、选区与前后锚点验证归属，再做有预算限制的文字差异比较。差异只是候选证据：专有词纠正、语气变化、改意图和无关编辑要分开。范围不明就放弃该样本，不从整个聊天输入框猜词。

Android InputConnection 可能返回空、截断或不支持某些文字更新；清空、失焦都不是可靠的发送回执。保存最后已观察的有效改稿即可，不承诺一定抓到最终文字。[Android 官方接口](https://developer.android.com/reference/android/view/inputmethod/InputConnection)。

## 推荐的更新方式

明确纠词形成热词候选；本人的持续表达支持文风；有归属的截图与本人陈述支持人物。模型生成的建议、没选的候选、发送状态未知，都不能伪装成对方事实或用户负反馈。

有增量时排队，在空闲和预算允许时合批。每批只带新增片段与相关旧记忆；超过上下文就切片，保留来源和处理位置。模型提出受限更新，本机核对来源与版本、保护手动修改、处理冲突，再可撤销地应用。重试同一批不重复强化证据。

已选：明确纠词自动入词且可撤销；文风变化和人物冲突先确认。具体触发条件、预算与可靠纠词的验证标准尚待确定，不固定五小时或任意证据次数。无需长期 Agent，也不覆盖设备目录。

## 存储与云端用途

建议图片压缩、去重并提供占用与清理入口。截图和原始录音的保留期限、备份容量仍待定；不能用“省上下文”为由悄悄删除原历史。

推理只发送本次必要材料；云备份只在有权益且本人开启时使用。开启备份不代表允许全库模型分析；免费本地保存也不代表使用云模型时数据完全不出设备。删除来源时，依赖该来源的自动记忆应能追溯并重新核验。

当前 0.4 的设备加密备份采用账号恢复方式，不是端到端加密；任务恢复缓存最长 24 小时。这是现有实现，不是已经确认的新保留策略，见[当前实现](implementation.md)。
