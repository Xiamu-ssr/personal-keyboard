# 历史、记忆与同步

目标契约。当前 APK 有本地资料、修订与手动备份；自动提取、云 ASR 接入、加密云同步尚未实现。

## 本地是主本

| 留下的材料 | 必需上下文 |
| --- | --- |
| 语音历史 | 原转写、可选改写、可信最终编辑、应用 / 人物范围、模型与设置版本 |
| 军师历史 | OCR 文字与来源、说话人及不确定性、用户意图、三条建议、选择与可信修改、引用记忆版本 |
| 学到的记忆 | 热词、文风、人物事实 / 事件 / 偏好分别存储；保留来源、修订和删除记录 |

不归档截图，不记录所有击键。建议不是对方的事实；选中不是发送，输入框清空也不能证明发出或删除。历史可删、可设期限。历史被删除后，尚未处理的证据作废，已有记忆显示“来源已删除”，由用户决定是否保留该记忆。

ASR 只取当前范围最近的少量文字，不能把整个历史当“近期上下文”。Message 现有接口每种角色最多 5 条、每轮合计 400 字符；用最新已确认转写和相关热词优先，不为凑轮次伪造助手回复。个人文风改写开关独立于 ASR 基础规整。

## 增量整理，不整库重写

    新历史 / 可信修改
      → 按人物与 token 预算组批
      → LLM 提取候选与证据
      → 校验来源、范围和版本
      → 本地事务合并，再推进处理位置

每约 5 小时检查一次，受 Android 后台调度约束；无新增不调用，可手动触发。每批预留输出空间，初始输入预算 8K token，随模型容量配置；单条过长按来源位置切片。跨片事实只带相关旧记忆和有界重叠，候选再按人物去重合并，不重新吞下全部原文。单次运行限制批数，积压续跑。

任务记录 `jobId / deviceId / fromCursor / toCursor / baseRevision / modelVersion`。模型输出 `proposals[{category,scope,subject,content,sourceIds,baseRevision,confidence}]`；来源必须在本批许可集合内，不能让模型编造证据。未知最终文本不参与纠错学习；反复出现的独立证据才支持长期文风，不把一次表达永久化。

程序校验结构、来源、身份与预算，再事务提交；同一证据不因重试重复计数。修订冲突保留为候选或重算，用户手改和删除优先，模型不复活已删项、不自动删除资料。处理游标只在提交后前进。派生记忆与原始历史分层，可重建而不冲掉人工资料。

## 工作流与执行环境

首版在手机用后台队列组织任务、调用文字模型，免建云端 harness。提取与合并是固定工作流：输入已知、输出固定，不需要 shell、浏览器或自主工具调用。

以后如需云端执行，可复用相同任务契约：

    input/manifest.json   任务、范围、游标与版本
    input/events.jsonl    本批最少历史，只读
    input/memory.json     相关旧记忆，只读
    output/patch.json     待校验候选

工作目录按任务隔离，用有界工作进程 / 池执行，无需每条任务重启整个容器。云任务返回补丁，设备校验并合并；绝不把云端目录覆盖回本机。若允许云端或供应商推理，它们必然接收本次所需明文；端侧加密备份不能掩盖这项独立的数据传输。

## 同步与登录分开

先接用户自有 WebDAV，配置服务地址、账号和应用密码，无需输入法账号。坚果云可作为默认示例；独立目录方便管理，但不冒充服务端目录级授权。后续用户增多，再考虑平台私有对象存储与登录服务。

上传客户端加密的增量包和清单，不同步运行中的 SQLite / WAL 文件。事件使用设备唯一标识和递增序号，实体使用全局 ID；增量携带版本、删除墓碑、包摘要与幂等标识。恢复时验证完整性并合并，冲突可见。新设备需恢复密钥或口令；Google / 微信登录只证明身份，不能自动解密数据。

云备份、让模型整理、向豆豆共享资料是三个独立目的。向豆豆共享按类别与人物授权，默认不含完整历史；断开连接停止后续传输。不同服务不共用长期模型账号和存储管理密钥。
