# 本轮决定 · 2026-10-21

这是一份目标规格。业务图播放的是模拟数据，不调用真实模型。已发布 APK 0.4 的实现差异见 [当前实现](implementation.md)，本轮没有重新发布 APK。

## 军师：一次图文推理，不做 OCR 前置

首发使用阿里云北京地域 **Qwen3-VL-Plus，非思考模式**。输入为临时截图、用户意图、适用热词 / 文风与相关人物记忆，Cloud 组装军师提示词。一次请求同时返回三条回复与有来源的文字上下文，不再先跑 OCR、再选是否看图，也不保留 OCR 降级路线。

返回约定：`replies[3]`、`contextEvidence.messages[{speaker,quotedText,sourceFrame,uncertain}]`、`contextEvidence.summary`、`uncertainties`。说话人无法辨认就标未知；模型读出的文字是可出错的观察，不是假定可靠的聊天原文。建议不是事实，填入不是发送。

军师收起键盘 → 等待布局稳定 → 截图裁切 / 限制像素 → Cloud → 图文供应商 → 返回校验 → 展开回复。图片只用于本次任务并及时销毁；本机历史保留必要文字、意图、来源与用户选择，后续记忆学习无需重传截图。失败显示重试，同一任务不重复结算。

选择理由：聊天气泡、头像、引用、表情和截图布局本来就参与理解。独立 OCR 会把画面转换成另一份待维护的中间材料；一期直接用图文模型简化这条链。代价是截图必须上传，图片 token 与模型误读需要计量和提示。这是产品架构选择，不声称已实测优于所有 OCR。

阿里云实时价格页列出的该模型在北京地域、输入不超过 32K token 时：输入 ¥1 / 百万 token，输出 ¥10 / 百万 token。截图按图像 token 计费，不能把一张截图当一个文字 token；实际上线前以相同聊天样本验收身份归属、引用与延迟。[官方模型说明](https://help.aliyun.com/zh/model-studio/models)、[官方计费](https://help.aliyun.com/zh/model-studio/model-pricing)。

## 历史：原文不覆盖，改稿另留证

一次语音 / 军师填入有一个全局 `recordId`：

| 字段 / 记录 | 存什么 | 在哪 |
| --- | --- | --- |
| `rawAsrText` | ASR 成功后的最终转写；军师为空 | 本机 UtteranceRecord |
| `rewrittenText` | 用户打开个人改写时的模型结果 | 同一记录 |
| `insertedText` | 实际填入编辑器的版本，是改稿对比基线 | 同一记录 |
| `lastObservedText` | 仍能归属于本次插入范围的最后一份有效改稿 | 同一记录的修订 |
| `EditEvidence` | 对比基线的多段差异、范围置信、来源修订和时间 | 本机独立表，关联 recordId |
| `finality` | `observed` / `unknown_after_clear` 等观察状态 | 不伪装成发送回执 |

Cloud 模型自己的润色不能算用户纠错。原始音频不留存，截图不进入备份；普通打字不抓取整段聊天历史。

先保存原始结果，填入成功再记录实际插入范围。用户继续修改时，输入法只观察自己填入的范围，合并约 300ms 的短时变动，保存非空有效快照。清空、失焦、编辑器不可读时保留上一份快照，不生成“整段删除”证据。如果用户点的是输入法提供的发送动作，先尽力刷新快照再交给宿主处理；不拦截、猜测或自动执行发送。

Android 的 InputConnection 能请求抽取文字、附近文字和可选更新，但编辑器可能返回空、截断或不支持。这意味着有些修改无法观察，不能承诺每一次发送前都能捕获。只在范围与修订明确时学习，不用补猜的数据凑完整链路。[Android 官方接口](https://developer.android.com/reference/android/view/inputmethod/InputConnection)。

## 差异算法与学习准入

本机先固定本次编辑器会话与插入范围，用前后锚点验证归属。按 Unicode 码点消除共同前后缀，再做有长度 / 时间上限的多段差异比较（bounded Myers）；超过预算或锚点不唯一即标为不确定，不把整段重写当一个专有词。

差异只是证据，后续文字模型分类为：专有词纠正、文风修改、事实 / 意图变化、无关或不确定。代码校验来源和准入：

- 清晰、可归属的专有词纠正可进入可撤销热词；“豆包→豆豆”成为识别偏好，**不是全局强制替换规则**，否则真的说“豆包”也会被误改。
- 文风至少需要三条独立、一致的来源支持；一次“今天想严肃一点”不改长期口吻。阈值是版本化产品规则，不是模型自报置信度就能绕过。
- 人物事实要有明确人物与直接证据；“今天累了”可成为带时间的状态，不自动推成永久性格。草稿和建议不成为对方事实；没选的建议也不是“不喜欢”。
- 手动资料受保护；冲突、范围不明或来源缺失留待确认。任何自动补丁都能解释来源和撤销。

Typeless 官方确认会把听写后的纠正词加入词典，但没公开底层监听算法。[官方说明](https://www.typeless.com/help/quickstart/history-and-dictionary)。开源 VoiceInk 的自动学习实现则有插入范围、唯一前后锚点及最终快照对比，可以借鉴“先证明修改属于这次插入”的边界；不能把桌面可访问性实现直接当安卓方案。[VoiceInk 源码](https://github.com/Beingpax/VoiceInk/blob/main/VoiceInk/Features/Dictionary/AutoLearn/FinalSnapshotDiffEngine.swift)。

## 整理：固定增量工作流，不启动通用 harness

本机约五小时检查一次；这是 Android 后台调度的期望周期，不是精确闹钟。没有新证据不调用。一次增量超过模型上下文就分片，未处理部分留在断点后，下批接着走，不塞进一个无限增长的会话。

流程固定为：**冻结增量边界 → 按预算组批 → 模型提取 → 按人物 / 类别合并去重 → 来源与版本校验 → 返回补丁 → 本机校验并提交 → 推进断点**。本机记忆主本不会交给模型自由写目录，Cloud 不需要给每个用户反复启动一个 harness 容器。

模型负责语义提取和建议；身份范围、token 预算、来源白名单、手动数据保护、冲突、幂等、版本与提交均由代码处理。完整字段及失败恢复见 [历史与记忆](memory-and-sync.md)。

文字整理继续使用 `qwen-flash`，个人改写和记忆提取共用供应商模型，分别使用各自版本化提示词；军师固定使用图文模型。这里选择调用分工，准确率和成本收益仍需真实样本联调验证。

## 图怎么读

大框是域；域内小框是真正的业务节点，空心端口接收、实心端口输出。箭头连接端口；跨域的节点连接复用一来一回两条总线。中间数据卡片按发生顺序进入历史，可上下滚动回看。只有一只模拟时钟，后置事件依赖前置事件，播放结束不乱序循环。

输入、留存与改稿、约五小时后整理、下次输入四个阶段都在同一个世界里。点击节点查看输入 / 输出；点击数据卡片查看具体端点。画布可拖动与缩放，页面本身不向下延长。
