# 豆豆输入法

Android-first keyboard, separate from Doudou Agent. App and PostgreSQL-backed Cloud are implemented. Enterprise Aliyun models are configured on Cloud; real fixture calls passed for ASR, advisor, rewriting and memory updates on 2026-10-22. 0.6 uses single-use invitations, account/password login and rotating recovery codes; SMS code and configuration have been removed. Payments remain disabled. Never call fixture tests real-user acceptance.

- Read spec/spec.yaml before changing behavior. Spec uses only YAML graph entities, packet contracts and short node details; no Markdown documents or document registry. Run npm run spec:build after changing its sources.
- Keep three product areas: app/, cloud/, spec/. Spec has two primary sections: fixed-color domain cards (基础域) and three business views (语音转录 / 军师模式 / 记忆更新). All views use the same fixed domain entities: App has history and a personalization cache; Cloud has proxy, accounts/entitlements, hotwords, style, and people as canonical records. Child entities are spatial nodes, not workflow actions. Between each domain pair draw exactly two straight lanes, one each direction, with no child ports, internal branches or extra edges. Ordered data cards scroll, shrink and fade between domains; one example clock drives their arrival. Fit the page to the viewport; pan/zoom only the canvas. Prompts and actions belong in data cards or contextual details. Never restore a global document library or extra graph filters.
- Distinguish confirmed requirements, research facts, recommendations and current code. Questions and speculative suggestions are not authorization to fix a policy. In particular, a five-hour learning schedule, evidence-count threshold, exact vision model and screenshot discard policy are NOT confirmed requirements. The user has selected direct multimodal advisor, Cloud canonical personalization with local caches, and automatic learning without Ask/Auto/Off options. Clear corrections may add hotwords reversibly; style changes and person-memory conflicts retain cautious confirmation. Recommendation demos must be visibly marked as pending choices.
- All commercial model traffic is App → Cloud → supplier. Cloud owns prompts, credentials, entitlement settlement and provider routes. Prompt capabilities explicitly name their model destination in the channel packet. No supplier credentials in the commercial APK.
- Welcome entitlements are once per account: 10,000 successful final ASR characters and 20 advisor generations. A successful more request costs one generation; failure/cancellation releases reservations, and original request retries never double-charge. Keep prices, grants and features versioned in cloud/config/plans.json. Paid plans remain drafts until their limits and prices are decided.
- The keyboard has one compact candidate/action row. Do not reintroduce permanent Input / Voice / Advisor tabs.
- Keyboard and settings are surfaces of one input-method App. Feedback is an underlying learning mechanism, not a fourth user mode. Vocabulary/style and voice reinforce each other; people/events are shared memory for typing, voice and advisor, with explicit subject and evidence scope.
- Advisor interaction: shrink → wait for host layout → capture → expand results → user selects a reply. Confirmed: final ASR text and advisor screenshots enter local history. 0.5 implements one multimodal request and local screenshot history; an owned practice screenshot passed a real Qwen3.8-Flash request from the production server. This does not prove capture or response quality in every chat App. Do not claim cloud/provider zero retention or capture success without evidence.
- Public Spec provides native screenshots, actual APK recordings and downloads. Online Android trial is cancelled; do not add an emulator host or device bridge unless the user requests it again. Public pages must never start or connect to the user's Mac or ADB.
- Local device demos display real Android output through Node/scrcpy and require an explicitly selected device. Keep resources bounded and stop after validation; restore real-phone IME/accessibility settings after temporary validation. Keep screenshots, web simulations and real model responses distinguishable.
- No raw chat screenshots, account addresses, credentials, personal profiles or device serials in Git. Runtime and screenshots belong under ignored .runtime/.
- Model prices need a dated official source and unit conversion. Personal subscription quota is not an unlimited production API entitlement.
- Local vocabulary, personal style and per-contact relationship memories are separate. Missing final text is not a negative example; skipped reply options are not dislikes.
- History has voice and advisor kinds. Advisor uses screenshots, related people/relationships, style and same-conversation 近期上下文; no separate hotword list. Keep source, actual inserted baseline and 结果稿, not an edit timeline. After insertion resultText starts equal to insertedText; user edits update resultText, and no edit does not mean an empty result. Diff insertedText against resultText, not the model's ASR-to-rewrite changes. Do not require send receipts for learning or mistake a draft for a chat fact. App submits incremental history revisions; Cloud validates LLM operations and transactionally commits canonical memory. App syncs complete changed records and tombstones into its cache. Track changes to old history and deduplicate evidence; do not train weights or add workflow nodes.
- Local text history and advisor screenshots are evidence. Cloud owns hotwords (standard text and observed variants), scene style profiles (short rules and examples), people (identity, individually identified facts and relations), sources and protected manual records. Devices cache them. Personal voice rewriting remains optional. Learning uses one complete current memory snapshot in EVERY request; only incremental history may be split. Do not retrieve subsets of old memory or replace people with summaries. Count the complete prompt/schema/memory/history using the pinned official Qwen tokenizer and chat template, add a protocol allowance, reserve output and respect both input and total context limits. This is a capacity budget, not an exact billable token claim; pause if real provider input usage exceeds it. Process batches serially per user, compare baseVersion and commit atomically before advancing the history cursor. Recompute on concurrent edits. Check proposed memory growth before commit; if full memory cannot fit even a minimum history batch, retain queued work and report capacity rather than silently truncate, filter, delete or advance. No fixed five-hour schedule or per-user filesystem harness. Personalization sync is a basic account capability; full history/screenshot backup remains paid. A real correction fixture passed model generation and domain validation; broad accuracy and real-user learning remain unverified.
- Report actual native, browser, device and model verification separately. Never label this demo a full Chinese input engine or real ASR until those are implemented and tested.

- Use 近期上下文 consistently for local recent task context; 历史增量 is the learning input, 个人记忆 is Cloud-owned personalization. App advisor uploads screenshot, conversation reference, recent context and intent only. Cloud retrieves related people and style itself; never upload canonical memory copies from App as the request contract. The target prompts live directly in spec/spec.yaml. Runtime cloud/prompts/ implements the same contract; keep both representations aligned.

- 0.7.2 product behavior: short space inserts a space; hold replaces the letter keyboard with a dedicated dictation surface. Release finishes and fills; the upper-left target withdraws this dictation, the upper-right target finishes with a newline. Returning to the bottom neutral region reverses a target selection before release. Real interim text uses an owned composing span; do not overwrite external edits. Advisor checks prerequisites first, then one tap captures and generates; replies wrap fully, tap fills, long press edits, and prior groups can be restored without another model request. Permission/login actions name their destination. My groups account/allowance, input, privacy and permissions instead of exposing a technical checklist. Preserve ordinary profanity and user stance; do not promise bypassing provider safety. Accessibility disclosure must say screenshots are uploaded for model inference and retained locally when history is enabled.

- 0.7.2 follows the official Doubao Android 1.5.2 held-space interaction, observed on the authorized old phone. Show only waveform, withdraw/newline targets and release feedback while held; release immediately restores typing with completion progress in the candidate row. The first user edit releases the composing span; late ASR or rewriting must never replace the edited draft, while final ASR can still enter raw history. Preserve the host editor and prior draft on cancel. More opens a keyboard-sized 2x2 grid with four real tools, never a native PopupMenu. Keep the single persistent voice entry on space. The tools grid also offers an explicit hands-free card for long speech; accessibility long-click uses the same capture route. This differs from Doubao's persistent tap-to-speak header. Do not claim complete Doubao parity. Product review must compare actual same-state screenshots and gestures, not infer good UX from tests or absence of overlapping text.
