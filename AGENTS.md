# 豆豆输入法

Android-first keyboard, separate from Doudou Agent. App and PostgreSQL-backed Cloud are implemented. Phone SMS and server model credentials are pending; payments remain disabled. Never call fixture tests live provider acceptance.

- Read spec/product.md, spec/interaction.md and spec/architecture.md before changing behavior. spec/spec.yaml is the visual product map; run npm run spec:build after changing its sources.
- Keep three product areas: app/, cloud/, spec/. Spec has two primary sections: fixed-color domain cards (基础域) and two business views (语音转录 / 军师模式). Both use the same fixed domain entities: App has history, hotwords, style, people; Cloud has proxy and accounts/entitlements. Child entities are spatial nodes, not workflow actions. Between each domain pair draw exactly two straight lanes, one each direction, with no child ports, internal branches or extra edges. Ordered data cards scroll, shrink and fade between domains; one example clock drives their arrival. Fit the page to the viewport; pan/zoom only the canvas. Prompts and actions belong in data cards or contextual details. Never restore a global document library or extra graph filters.
- Distinguish confirmed requirements, research facts, recommendations and current code. Questions and speculative suggestions are not authorization to fix a policy. In particular, a five-hour learning schedule, evidence-count threshold, exact vision model and screenshot discard policy are NOT confirmed requirements. The user has now selected direct multimodal advisor and automatic, reversible hotword additions for clear corrections; style changes and person-memory conflicts require cautious confirmation. Recommendation demos must be visibly marked as pending choices.
- All commercial model traffic is App → Cloud → supplier. Cloud owns prompts, credentials, entitlement settlement and provider routes. Prompt capabilities explicitly name their model destination in the channel packet. No supplier credentials in the commercial APK.
- Welcome entitlements are once per account: 10,000 successful final ASR characters and 20 advisor generations. A successful more request costs one generation; failure/cancellation releases reservations, and original request retries never double-charge. Keep prices, grants and features versioned in cloud/config/plans.json. Paid plans remain drafts until their limits and prices are decided.
- The keyboard has one compact candidate/action row. Do not reintroduce permanent Input / Voice / Advisor tabs.
- Keyboard and settings are surfaces of one input-method App. Feedback is an underlying learning mechanism, not a fourth user mode. Vocabulary/style and voice reinforce each other; people/events are shared memory for typing, voice and advisor, with explicit subject and evidence scope.
- Advisor interaction: shrink → wait for host layout → capture → expand results → user selects a reply. Confirmed: final ASR text and advisor screenshots enter local history. Direct multimodal interpretation is now selected; its exact model and runtime migration are not implemented by this Spec change; spec/design-options.md explains its tradeoff with local OCR. Published 0.4 retains OCR/optional-image behavior and does not yet save screenshots. Do not claim cloud/provider zero retention or capture success without evidence.
- Public Spec provides native screenshots, actual APK recordings and downloads. Online Android trial is cancelled; do not add an emulator host or device bridge unless the user requests it again. Public pages must never start or connect to the user's Mac or ADB.
- Local device demos display real Android output through Node/scrcpy and require an explicitly selected device. Keep resources bounded and stop after validation; restore real-phone IME/accessibility settings after temporary validation. Keep screenshots, web simulations and real model responses distinguishable.
- No raw chat screenshots, account addresses, credentials, personal profiles or device serials in Git. Runtime and screenshots belong under ignored .runtime/.
- Model prices need a dated official source and unit conversion. Personal subscription quota is not an unlimited production API entitlement.
- Local vocabulary, personal style and per-contact relationship memories are separate. Missing final text is not a negative example; skipped reply options are not dislikes.
- History has voice and advisor kinds. Advisor requests use current screenshots, relevant person/relationship memory, the user's style and same-conversation confirmed final messages; no separate hotword list or raw-ASR substitution for sent context. Proposed minimal records retain source, actual inserted baseline and one latest valid outcome with evidence state, not an edit timeline. Android standard IME APIs cannot guarantee final sent text across all host apps. The recommended learning split is App selects incremental revisions, Cloud budgets/chunks and calls the supplier LLM, App validates proposals and commits local memory plus processing positions. Track updates to older records and deduplicate evidence across revisions; do not train weights or turn this into new graph nodes.
- Local textual history is evidence, separate from derived memory. Personal voice rewriting is optional. Incremental, event/idle-based batching is a recommendation; its trigger and automatic application policy remain undecided. Validate evidence and revisions before applying model proposals. Never overwrite device directories with model output. Free accounts retain data locally. Paid managed cloud sync must not expose storage-provider settings. Cloud sync and model analysis have separate scopes; see spec/memory-and-sync.md.
- Report actual native, browser, device and model verification separately. Never label this demo a full Chinese input engine or real ASR until those are implemented and tested.
